# 配速建議 — 五個概念方案

2026-10-31，使用內建 imagegen 產生。尚未加入 App。圖片是探索布局的概念稿，
其中的日期、模型名稱、額度計數與曲線只是示意；以下公式與限制才是後續實作依據。

## 共通規則

- 每個服務、模型及限制窗口獨立計算。不把 Claude、Codex、Gemini 額度合併，
  也不直接比較不同窗口的百分點，因為它們的總量分母可能不同。
- 「20 個百分點」指總額度的 20%，不是剩餘 80% 再乘以 20%。
- 時間使用精確剩餘毫秒換算，不把 3.2 天無條件進位成 4 天。
- 短於一天的窗口改用每小時配速。缺少重置時間、資料過期或窗口已重置時，
  不顯示假的可用建議。滾動窗口恢復的額度不是保證一次全部回滿。
- 這是規劃參考，不保證還能送幾個請求或產生多少 token；任務成本會變。
- 歷史方案只需本機時間、窗口識別、重置時間與百分比，不需存 token／email，
  沿用既有輪詢，不額外提高服務查詢頻率。

## 方案

| 方案 | 示範公式 | 適合誰 | 需要的資料 |
|---|---|---|---|
| 01 每日均分 | 剩餘 80pt ÷ 4 天 = 20pt／天 | 每天使用量穩定 | 現有剩餘比例、重置時間 |
| 02 保留緩衝 | (80pt − 保留 10pt) ÷ 4 = 17.5pt／天 | 擔心臨時用盡 | 現有資料＋自訂保留量 |
| 03 今日配速儀表 | 今日固定目標 20pt − 本機觀測今日已用 10pt = 今日剩餘建議 10pt | 長時間工作，想看今天還能用多少 | 當日基準快照及固定的今日目標 |
| 04 工作日排程 | 工作量權重 1:2:1:0，分配 80pt → 20/40/20/0pt | 明天趕案、週末少用 | 手動一般／重度／休息排程 |
| 05 趨勢預警 | 80pt ÷ 25pt／天 = 3.2 天，較 4 天重置早 0.8 天（約 19 小時） | 希望提前知道可能用盡 | 同一窗口足夠的本機觀測紀錄 |

03 的當日目標要固定，不能每次用最新餘額重新計算後又扣一次今日用量。
若沒有日初基準，或離線期間無法判斷窗口重置，就退回 01／02 並標記資料不足。
05 必須分隔重置前後的紀錄；不足取樣時間或有額度異常跳動時不預測，不偽造信心值。

建議先選 **02 為預設、01 為可選模式**；累積可靠紀錄後，再加入 03 與 05。
04 則適合想手動控制工作排程的人。
